# CatooBot v1.2 设计文档 — Human Conversation Runtime + Character Continuity

> 本文档先回答规格书 §6 的 15 个审计问题（基于当前真实代码），再给出实现设计。
> 约束：最小侵入（§181）——稳定模块用 Adapter/ContextProvider 接入，不重写。

---

## Part 1. 架构审计（2026-09-30，基于真实源码）

### Q1 一条 QQ 消息经过哪些模块？

```
NapCat → OneBot Server (server.py:216 每事件一个 asyncio.create_task)
       → parser → bot._on_event → event_bus.emit（同一条消息的 handler 串行）
       → CoreRouter.on_message（日志 + user/group upsert）
       → CharacterPlugin._on_private / _on_group
           → media normalize / vision（如有媒体）
           → behavior.consider_private 或 social.decide（群）
           → _respond：character.respond（ContextBuilder→AIEngine→router→provider）
                      → processor.sanitize → response_planner.plan_reply（timing+chunker）
                      → _attach_expression → response_delivery.deliver → QQ
           → 后置：observe_conversation、conversations append、social.after_reply、
                   extractor.schedule、log_event
```

### Q2-Q9 决策与状态归属

| 问题 | 答案 |
|---|---|
| Q2 是否回复 | 私聊 `behavior.consider_private`（仅 DND/硬阻断）；群聊 `social.decide`（结构化），social 关闭时 `behavior.consider_group` 概率兜底 |
| Q3 回复什么 | `character.respond`（ContextBuilder 组 prompt → AIEngine） |
| Q4 何时回复 | `ReplyTiming.compute`（planner 阶段）；chunk 间隔在 delivery |
| Q5 短期上下文 | `ConversationManager`（内存 dict + `conversations` 表，20 条截断，无 turn 概念） |
| Q6 长期记忆 | `MemoryManager`（memories + 向量库，后台 extraction） |
| Q7 当前活动 | `ActivityRuntime` episode（v1.0，含 activity_detail/tags）→ 同步进 CharacterState |
| Q8 关系状态 | `RelationshipManager`（stage / interaction_count / preferred_tone / notes） |
| Q9 对话主题 | 群：`TopicManager` + `ThreadManager`；**私聊无主题管理** |

### Q10 回复后发生的状态变化

mood nudge（observe_conversation）、conversations append、relationship.record_interaction、
social.after_reply（thread/observer）、memory extraction 排程、world interaction note、
delivery.last_sent_ids、expression.note_sent、metrics。

### Q11 哪些状态没有写回（v1.2 的机会点）

- 无 turn 分组、无 generation 记录、无打断/过期标记；
- 无 unfinished_thought / open_loops / shared_experience / interaction_profile / affect；
- 私聊主题无动量/疲劳；
- 用户打断时旧响应毫无感知。

### Q12 重复判断

- ready / mentions / 短文本守卫在 plugin 与 behavior/social 各一份；
- presence 硬阻断在 `consider_*` 与 `social.policy.block_reason` 各查一次；
- 空文本+媒体守卫与 placeholder 逻辑在 plugin 内。

### Q13 逻辑冲突

- **`character/context.py` 群聊写死「只回应 @你的消息，其他人聊天不要插话」——与 v0.9
  Social Cognition 直接矛盾（§85 要求删除）**；
- `behavior.group.participation_probability` dice 与结构化决策并存（social enabled 时已绕开）；
- chunker 概率分段与风格规则「不要习惯性两段」并存。

### Q14 多处 Context 生成

CharacterContextBuilder（主）、SocialContextBuilder（观察）、extraction/observer/agent
prompt——各任务自身合理；但主 prompt 缺统一装配层，continuity/profile/shared 无入口。

### Q15 并发与过期回复（v1.2 核心结构问题）

**是。** `server.py:216` 每条消息一个独立 task → 用户连发 N 条 = N 个并行 `_respond`
= N 次 AI 调用 + N 条回复。无 per-session 锁、无 generation id、无 stale 检测、
无取消机制。这正是 §15-§18 要解决的。

## Part 2. 设计

### 新包 `app/conversation/`（Conversation Turn Runtime）

| 模块 | 职责 | 关键决策 |
|---|---|---|
| `models.py` | TurnMessage / ConversationTurn / TurnClassification / ConversationDecision / ResponseStep | 纯 pydantic，结构化，无思维链 |
| `buffer.py` | MessageBuffer + 动态 Debounce | gap 触发关闭（非固定等待）：间隔阈值受 消息长度/是否在生成/群私聊/角色状态 调制 |
| `classifier.py` | TurnClassifier | **纯规则**（correction/interruption/follow_up/topic_shift/closing/multi_message），不调模型 |
| `runtime.py` | ConversationTurnRuntime | per-session turn 生命周期；flush 时生成唯一 generation；**session 级锁**（同 session 一个在途生成）；stale 检测（LLM 返回/planner/delivery 三处校验）；旧生成不发送 |
| `decision.py` | ConversationDecisionEngine | rules + state + social context 组合；respond/intent/engagement/message_shape/should_ask；**连续追问守卫**；无 random |
| `repair.py` | ConversationRepair | correction/interruption 时废弃旧响应 + 重新生成；repair_count 防循环 |

入口适配：`plugin._on_private/_on_group` → `bot.conversation.submit(event, decision_ctx)`。
群消息仍逐条进 social.monitor（保持 v0.9 数据流），但**参与决策在 turn flush 时**以合并
文本跑一次（§82/§83 one conversational burst）。@/回复她的消息仍即时直通（不停顿）。

### 新包 `app/continuity/`（Character Continuity）

| 模块 | 职责 | TTL |
|---|---|---|
| `models.py` | CharacterContinuityState / OpenLoop / SharedExperience / InteractionProfile / AffectiveContext / MicroEvent | 字段全部 value+confidence+updated_at+reason_code |
| `store.py` | DB 持久化 + 加载时 TTL 衰减 | recent_emotion 分钟~小时；current_interest 小时~天；open_loop 天；shared_experience 长期 |
| `open_loops.py` | OpenLoopManager | open/paused/completed/abandoned/expired |
| `shared.py` | SharedExperienceManager + 规则 Extractor | 相关性召回（topic/entity/user），不每条加载 |
| `profile.py` | InteractionProfile + PatternLearner | 连发习惯/追问率/活跃时段/表情习惯，统计+衰减+置信度，非永久标签 |
| `affect.py` | AffectiveContext | 7 维 0-1，事件驱动（+reason），指数衰减，**禁止每 tick 随机** |
| `updater.py` | ContinuityUpdateEngine + RelevanceEvaluator + 后台更新队列 | 回复后 asyncio.create_task，不阻塞；只有有意义内容入库 |

### 集成点（最小侵入）

- `character/context.py`：新增可选层（continuity / interaction_profile / shared_experience /
  turn 摘要）；**删除群聊「只回应@」死规则**（§85）；返回 ContextTrace（included/excluded
  + 原因）供 WebUI Context Inspector。
- `behavior/models.py`：ResponsePlan 增 `steps: list[ResponseStep]`（text/sticker/pause），
  delivery 优先走 steps，缺省回落 chunks+attachment（兼容旧测试）。
- `response/delivery.py`：`deliver(..., is_current)` 在首条与每个 chunk 之间校验 generation，
  过期即中止发送。
- `response/timing.py`：已支持 extra_factor；decision 层把 momentum/focus 折算进去。
- `world`：MicroEvent 流（world tick 产生，TTL 内有效），`world_context()` 增
  `micro_events`；open loop 与 activity 关联推进。
- `social`：不改内部，新增 `observe_only()` 逐条记录 + `decide_for_turn(merged_text)`。
- `media/expression`：输入增加 affect/relationship/recent_expression；重复语义表情守卫。
- `initiative`：topic candidate 增加 source=naturalness（open_loop/shared/recent_event）。
- `memory`：不改（turns 不入 Memory，§22/§159）。
- `relationship`：stage 保留；quality 分由 shared_experiences/事件推导（事件依据，非计数）。
- DB：migration 12 —— `conversation_turns` / `open_loops` / `shared_experiences` /
  `interaction_profiles` / `continuity_state` / `affective_events` / `micro_events`；
  **复用现有 `conversations` 表作为 turn messages 存储**（§108 不重复建表），turn 记
  message_ids。
- 配置：`conversation:` / `continuity:` 两段，全部可关。
- WebUI：/conversation 页（dashboard + turn explorer + continuity inspector +
  context inspector + dry-run replay）。

### 明确不做

不做隐藏思维链；不用 random 决定社交/表情/沉默；turns 不自动入 Memory；
普通图片仍永不进 StickerSelector；Agent 仍不直接产出最终回复；
不为拟人而故意撒谎/装忙/制造错误（§177）。
