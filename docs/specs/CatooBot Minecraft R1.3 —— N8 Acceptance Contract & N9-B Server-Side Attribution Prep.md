# CatooBot R1 Closure Adjudication — N8 验收合同对账与 N9-B 服务端归因专项准备

## 1. 本轮裁决

本轮目的不是强行将 R1 改成 PASS，而是基于当前 `origin/main`、R1 最终报告和已批准的残余缺口任务书，统一 N8 的验收口径，并明确 N9-B 的实际关闭条件。

初始状态应记录为：

- 总体：`PARTIAL`
- R1.1：按现有证据维持 `PASS`
- R1.2：按已批准的原始任务书重新核对，不得仅凭额外的 N8 五次受控触发结果自动判定
- R1.3：`PARTIAL`，N9-B 仍是未关闭的真实产品缺口
- R1.4：按现有发布及 CI 证据核验

先确认最新 `origin/main` SHA、工作区状态、实际运行版本和 CI 状态。报告中的历史 SHA 不能代替本轮基线核验。

## 2. N8：按原任务书重新裁定

重点阅读：

`docs/specs/CatooBot Minecraft R1.1 —— Residual Gap Closure.md` §5、§13

以及：

`docs/specs/CatooBot R1 Real-World Perception & Navigation Reliability Report.md`

### 必须核验的合同

1. `path_update(status='timeout')` 且仍存在可用路径：不立即失败；后续只有通过真实位置复核才能成功。
2. `path_update(status='timeout')` 且无可用路径：结构化 fail-closed，不能报告成功。
3. STOP/CANCEL/TIMEOUT 优先落终态；迟到的 `goal_reached` 不得翻案。
4. 成功和失败分支保留足够的导航 trace/detail；目标位置、实际位置、距离、半径与失败原因必须可审计。
5. Goal/listener 清理和唯一终态不回退。

逐条核验现有代码和测试，而不是仅凭 `84/84` 的总数判定。若有缺失，先定位缺失断言，再按最小范围补齐。

### 自然 timeout 探针的裁定

依原任务书规定：

- 确定性 E2 契约是强制验收项。
- 需要尝试真实依赖探针，但自然触发不稳定时应记录 `DEVIATION`。
- 不得更改生产默认 `thinkTimeout`、`tickTimeout`、`MOVE_TIMEOUT_MS`、`MOVE_TO_RADIUS`，也不得扩大安全测试区域来伪造通过。

当前报告的五次受控触发 `0/5` 应保留原始证据，但不得在没有正式验收变更的情况下，自动升级成原任务书从未规定的硬性五次真机要求。

如果发现后来确实批准了该项变更，先记录变更来源和验收版本，再依新合同执行。

若原任务书的所有必需 E2 检查均已通过、真实依赖探针已按要求尝试，则按原合同裁定 N8 的契约结果及 E3 偏差；不要再为了追求触发次数而无依据修改参数。

## 3. N9-B：保留 BLOCKED，不做文字性过门

当前决定性事实是：在真实 `WAITING_ACTION` 窗口内，外部操作移除了目标方块，真实读数变为 `air`，但任务终态仍为 `SUCCEEDED`，归因只有 `SELF_INFERRED`，且 `strict_self_proof=false`。

要求：

1. 保留该失败证据以及基于时间阈值的错误硬门撤回记录。
2. 不得把当前实现描述为已经满足“目标消失时 fail-closed”。
3. 不得仅修改测试标签、放宽断言或改写验收措辞，将 N9-B 标为 PASS。
4. 不在本轮直接新增服务端能力，也不修改正式服务器配置。
5. 审计正常真实挖掘样本中 `SELF_CONFIRMED`、`SELF_INFERRED`、`AMBIGUOUS` 的分布及现有消费路径，评估仅对非严格归因结果实施保守终态策略会造成什么影响。
6. 总裁定继续保持 `PARTIAL`，直到有合格的关闭证据。

## 4. 独立的服务端归因方案准备

新增一份设计方案，供后续单独批准实施。本轮只做设计，不实现或部署模组。

目标服务器为 Minecraft 1.21.1 Fabric。优先评估原生 Fabric 服务端事件机制，例如 `PlayerBlockBreakEvents.AFTER`，不要直接假定 Bukkit 插件可以原生运行在现有服务器上。

方案必须覆盖：

- 精确玩家 UUID、维度、目标坐标、破坏前后的方块状态及可信服务端事件时间。
- 如何将服务端事件与唯一活动的 `action_id`、目标坐标和执行时间窗关联。
- 外部 `/setblock air` 与真实玩家破坏的区分。
- 不同玩家破坏同一坐标、重复事件、迟到事件、事件冲突、服务器断线、STOP/CANCEL 与重启。
- 只读事件传输的认证、完整性、防重放和连接失败语义。
- 服务端模组不直接执行采集、不调用 Minecraft 产品工具、不提供授权旁路。
- 无匹配事件、多个可能匹配、身份不可信或数据过期时，必须返回 `UNKNOWN` 或其他明确的非成功结果。
- 不将 `BLOCK_REMOVED` 等同于掉落、拾取、库存净增或任务整体成功。

设计还需说明兼容性、依赖版本、部署与回滚方式、数据协议、失败模式、测试矩阵及验收成本。

## 5. 文档与最终交付

更新现有 R1 报告时必须追加更正，不覆盖旧版本、原始日志或首次失败记录。

交付内容：

1. 当前远端/工作区基线核验。
2. N8 按原任务书逐项核验的证据矩阵。
3. 对五次受控触发要求是否属于正式 DoD 的明确裁定。
4. N9-B 当前 BLOCKED 的证据、根因、影响及关闭条件。
5. 服务端归因设计方案，不包含未经批准的实现。
6. 根据真实 DoD 更新分项和总体裁定；证据不足时保留 `PARTIAL` 或 `BLOCKED`。
7. 所需测试、CI、受保护区域、Git diff 与仓库卫生结果。

禁止为了获得 PASS 而修改未正式批准的验收要求。本轮完成验收对账后停止，不创建新的 Follow-up 循环，也不宣称 N9-B 已关闭。
