# CatooBot Server-Side Block Attribution — P1 只读真实服务器实验

## 授权范围

批准执行 P1，不批准 P2 或 P3。

本轮只允许创建、构建、部署和验证一个仅记录日志的 Minecraft 1.21.1 Fabric Stub Mod。不得接入 CatooBot 产品终态，不得实现登记协议、HMAC 事件传输或新的归因消费逻辑。

不得修改现有授权链、工具白名单、Policy、确认门、数据库 schema 或生产执行路径。不得让 Stub Mod 执行游戏动作或修改世界。

## 实验 1：确认模组及监听器真实运行

记录：

- Minecraft、Fabric Loader、fabric-api 与 Java 的实际版本；
- Stub Mod 构建产物哈希、启动日志与监听器注册结果；
- 测试服务器标识、会话和维度；
- 每次测试唯一编号、目标坐标、测试前的真实方块状态。

若模组没有可靠启动证据或正向对照未触发事件，应判该轮实验无效，不得把“没有事件”当作预期结果。

## 实验 2：三组对照

A. 使用 `/setblock` 将测试目标改为 air。

B. 在生存模式下让罐头正常挖掘一个测试目标。

C. 让另一名玩家挖掘另一个测试目标。

每组记录事件是否触发、事件中的玩家标识、维度、坐标、回调提供的破坏前方块状态，以及回调中真实读取的当前方块状态。

每组测试后独立读取世界状态；只在专用测试目标上操作，并确认测试夹具已恢复或明确记录未恢复原因。

不得凭空补全未触发的事件。无事件必须保留为“未观察到该事件”，不要直接推断为已经证明的外部操作。

## 实验 3：验收与报告

通过条件：

1. Stub Mod 已可靠启动并登记监听器。
2. 三组对照均有可复核的测试前后状态和原始日志。
3. 已准确记录所选事件是否在每组场景中实际触发。
4. 没有修改产品动作行为、授权机制或世界动作执行链。
5. 能够解释每种结果的证据边界与未确定事项。

报告必须保留第一次实验失败及重试记录，明确区分实测事实、推断和仍未验证的假设。

不得自动开始 P2 或 P3，不得因为 P1 实验结果符合预期就宣称 N9-B 已关闭。N9-B 仍保持 BLOCKED，直到后续获得可信唯一匹配的服务端归因证据，并完成 P3 真实执行窗口复验。
