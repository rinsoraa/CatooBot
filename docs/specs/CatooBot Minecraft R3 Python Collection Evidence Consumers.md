## 问题与合同

1. 纯消费者复核当前冻结采集步骤：schema/类型、严格 break、目标坐标/种类、action、Minecraft session、服务端 session/ref/seq、actor UUID、维度、协议、reservation/event、唯一 drop UUID/实体 ID/物品/数量及 pickup 关联。数量和 ID 必须为有界真整数；不把 bool、字符串或未知版本转换为有效事实。任务的用户会话与 Minecraft 连接会话是不同命名空间，分别依赖原授权和证据关联。
2. 已完成的采集 dig 必须先有完整 break/drop 图，才可派发后续步骤；已完成 pickup 必须与同一 dig 及其解析后参数精确相符。结束与恢复后推进重新检查持久化证据，旧缓存的“验证成功”不得跳过。不同 dig 不复用 break/drop/pickup 身份；不完整、重复贡献或跨连接/实例证据保持明确非成功，不自动重发世界动作或增加预算。
3. 同一纯消费者用于任务终态及正向技能资格，旧成功记录不凭 SUCCEEDED/库存增量取得采集技能或采集成功记忆。缺证据属于不可判定，不作为方法失败的反例计分。既有非采集 P3 原子破坏、探索、合成和取消/过期/授权语义保持。
4. 资源和权限集不变，MEDIUM 默认关闭；不新增执行器、表或迁移，不抬高 TTL、重规划、等待、距离和动作上限。旧原始日志、数据库和世界备份不改写。
