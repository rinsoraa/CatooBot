# CatooBot Server-Side Block Attribution — P2 影子模式实施任务书

## 1. 授权与范围

审查裁决：P1 PASS，批准进入 P2 实施与影子验证。

本次授权仅涵盖：

- Fabric 服务端归因模组的最小实现；
- 当前 bot 会话与服务端会话的绑定；
- `action_id` 登记、唯一事件关联与认证传输；
- CatooBot 侧归因事件接收、审计和影子统计；
- E2 自动化测试与受控真实服务器验证。

**严格禁止：** 修改正式任务终态、接入成功判定、放宽授权或确认门、改变工具白名单、实施 P3 或宣称 N9-B 已关闭。

当前产品行为必须保持不变。影子模式可以记录“如果启用严格归因，本次动作将得到什么结论”，但不能影响原有任务的执行、成功或失败结果。

实施和真实服务器部署应采用可独立回滚的分支及测试环境。若没有隔离测试服务器，不得直接重启或改动现有生产服务器；先完成代码和 E2 验证，待生产部署另行获准。

## 2. 开工基线

先核验并记录：

- `origin/main` 当前 SHA；
- 当前工作区与镜像状态；
- CatooBot、Minecraft Runtime、服务器实际加载版本；
- P1 报告、设计 v2 与 P1 原始日志的可追溯位置；
- 依赖锁定、现有配置与受保护区域；
- 当前 dig 的真实终态路径，以及 `SELF_INFERRED` 被转换为成功的所有调用位置。

不得假设之前报告中的 SHA 或当前运行进程一定对应最新代码。

## 3. 服务端模组

使用 Minecraft 1.21.1 Fabric 和已验证的 Fabric API 版本建立可复现的正式源码与构建流程。不得继续只依赖一次性本机编译产物。

模组职责仅限会话管理、动作登记验证、玩家破坏事件观察与只读事件传输。

### 3.1 会话绑定

服务端在玩家加入时维护：

- `session_ref`；
- `session_seq`；
- 服务端实际观察到的玩家 UUID；
- 当前会话有效性。

明确区分离线模式 UUID 与在线认证身份。禁止将玩家名称直接作为唯一的安全身份。

同名重连、服务器重启或会话替换时，旧会话及其未消费登记必须失效。迟到事件不得绑定到新会话。

### 3.2 动作登记

CatooBot 在派发 dig 前，通过经过认证的回环接口提交：

- `session_ref` 与 `session_seq`；
- `action_id`；
- 单次使用的 32 字节随机 nonce；
- 维度、整数坐标和 `expected_block`；
- 服务端限制范围内的 TTL。

服务端必须自行读取目标位置，验证维度、坐标与预期方块。任何字段缺失、目标不匹配、登记响应不确定或会话失效时，都不得产生有效的严格归因登记。

服务端 TTL 使用自身单调时钟计算，不比较 Java 与 Node.js 两个进程的绝对时间。

每个有效登记应唯一对应一个活动动作。并发候选无法消歧时，必须拒绝严格匹配。

## 4. 事件生成与关联

使用 P1 已验证的 `PlayerBlockBreakEvents.AFTER`。

事件至少包含：

- `event_id`；
- `session_ref` 与 `session_seq`；
- 服务端实际观察到的玩家 UUID；
- `reservation_id`；
- 维度与目标坐标；
- `block_before`；
- 回调内独立读取的 `block_after`；
- 事件关联结果和拒绝原因。

只有服务端观察到的可信玩家破坏事件、当前有效会话、唯一有效登记以及完全匹配的目标，全部成立时，影子判定才可以记录 `SELF_CONFIRMED` 候选。

事件回调中的 `BlockState` 参数是破坏前状态。读取破坏后状态时必须进行显式世界查询。若查询结果缺失、被其他模组改变或产生冲突，应记录未知状态，不得猜测。

未登记的其他玩家破坏可以依据真实玩家身份与目标观察记录为外部玩家破坏证据。但对于 `/setblock`：

- 若目标消失且没有对应的玩家破坏事件，记录 `UNKNOWN`；
- 不得仅凭缺少事件就记录 `EXTERNAL_CONFIRMED`；
- 不得将未知归因视为挖掘成功。

## 5. 认证与幂等

实现前述设计 v2 的本地认证、HMAC-SHA256、单次 nonce、事件 ID 幂等及会话防重放要求。

额外要求：

1. 仅监听 `127.0.0.1`，非回环请求拒绝。
2. 密钥只保存在私有配置中，不进入 Git、不写日志。
3. 认证失败或重放事件不得成为有效归因证据。
4. 一个 `reservation_id` 只能被消费一次，一个 `action_id` 只能关联自己的登记。
5. 服务端重启、断线、旧会话失效后，所有相关待匹配记录都不得继续生效。
6. 归因事件接收失败不能阻塞 STOP/CANCEL。
7. 对事件验证、唯一匹配、消费与审计必须明确幂等和竞态语义。

P2 只对影子状态进行记录；不接入任何现有终态转换。

## 6. 影子模式隔离

影子模式必须显式启用，默认关闭。

- 关闭状态：行为与当前版本一致。
- 影子状态：收集登记、事件、关联候选、未知原因及影子判定；不参与执行决策。
- 严格执行状态：本轮不得实现或启用，留待 P3 单独审批。

必须保证影子代码不会修改现有 dig 成功条件、库存验证、授权、确认门、任务状态或世界动作执行顺序。

在同一真实挖掘样本中，可同时记录现有产品结果和影子归因结果，以便检查错误成功风险。任何影子结果都不能反向修改真实任务终态。

## 7. 测试矩阵

### E2 自动化测试

必须覆盖：

- 登记成功、登记拒绝、响应不确定；
- 正常事件唯一匹配；
- `/setblock` 后无玩家事件；
- 另一玩家在同坐标破坏；
- 玩家 UUID、会话、维度、坐标和方块前置条件不匹配；
- 重复事件、重复 nonce 和事件重放；
- 多候选登记、过期登记；
- HMAC 错误、token 缺失、通道断开；
- 服务端重启和同名重连；
- STOP/CANCEL 与事件同时到达；
- 迟到事件不改变既有终态；
- 破坏确认与掉落、拾取、库存净增严格区分。

所有拒绝与未知情况均必须有可审计原因码。

### E3 真实服务器验证

至少完成以下三类对照：

1. 罐头正常挖掘；
2. 活动登记期间，外部 `/setblock` 将目标移除；
3. 另一玩家移除目标。

建议积累至少 10 个正常挖掘样本，以及每类外部操作至少 5 个受控样本。样本量不足时如实标记，不以单次成功推断总体可靠性。

每个样本记录登记、事件、会话、目标状态、影子判定与当前实际任务终态，并保留首次失败及后续重试记录。

必须确认正常挖掘可以唯一匹配、`/setblock` 不被虚构成玩家破坏、另一玩家事件不会被关联到罐头自己的动作。

## 8. 影子统计与通过条件

影子统计至少包括：

- 有效登记数、被拒绝数和过期数；
- `SELF_CONFIRMED` 候选数；
- `UNKNOWN`、`REJECTED` 与外部玩家破坏证据数；
- 无法唯一匹配和重复事件数；
- 通道错误、迟到事件和重连失效次数；
- 正常挖掘候选匹配率；
- 外部修改导致目标消失时的未知归因比例；
- 影子判定与当前产品终态之间的差异。

必须区分“未观察到事件”和“已经证实外部造成变化”。不得把未知事件计入外部归因成功率或严格自证比例。

P2 通过条件：

1. 服务端会话与 UUID 绑定经真实日志确认；
2. 正常挖掘、外部修改与他人破坏均得到可复核的影子判定；
3. E2 竞态矩阵通过；
4. E3 受控服务器样本可关联至唯一动作；
5. 影子模式对产品终态的影响为零；
6. 断线、重启、认证失败、迟到及重复事件符合既定契约；
7. CI、凭据扫描、类型检查、格式检查及仓库卫生通过；
8. 构建产物可复现，回滚和禁用流程完成验证。

## 9. 交付与停止条件

交付：

- 服务端模组源码与可复现构建方式；
- CatooBot 侧影子接收和统计实现；
- E2 与 E3 完整矩阵、原始日志和失败历史；
- 真实影子匹配统计与已知边界；
- 配置、部署、禁用和回滚说明；
- 更新后的归因设计与阶段报告；
- Git、CI、保护区和凭据审计结果。

完成后停止，不进入 P3，不修改正式终态行为。

N9-B 仍然保持 BLOCKED，直到另行批准 P3，并在严格归因逻辑接入后取得 `strict_self_proof=true` 的真实执行窗口证据。
