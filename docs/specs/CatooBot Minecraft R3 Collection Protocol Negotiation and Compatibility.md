# R3 任务书：采集协议能力协商与兼容拒绝

开工前归档：2026-10-20。发布基线仍为 `d121127ef5b78016430c56a6c3f15f9d2a4cb6a4`；上轮冻结候选 4947 Python、静态检查及真实 Provider 9/9，通过记录见统一采集准入报告。阶段保持 R3，原 G1–G4 与 R4–R8 全部保留。

## 已定位的缺口

当前签名 `/session` 与 `/reserve` 只有 schema 1，不声明是否支持独立 drop/pickup。客户端在严格模式可用时，可能先在旧服务器挖掘，之后才发现 collection 不可证明。拾取事件还未完整对照预约的 break reservation；drop UUID/物品/数量的消费者边界也需收紧。

## 冻结合同

1. 以有界字符串 `catoobot.collection.v1` 表达采集证据协议，通过已签名 session 声明、预约请求和已签名回执逐次确认。缺失、未知版本、类型错误、回执降级或取消后的迟到回复均不得开始采集世界动作。不得以模组名称/版本日志或 HTTP 200 猜测能力。
2. 新客户端仍支持原有 P3 单次严格破坏协议；新服务器对无采集协议字段的旧 P3 预约保持原语义。没有采集声明的旧服务器不能被用来执行 require_collection。严格拾取必须具有采集声明和回执，不自动降级为附近实体或推断证据。
3. 采集消费者只接受本次已登记 break 的准确 UUID/实体 ID、当前 actor/session/dimension、规定物品和数量。拾取事件必须对照同一预约里的 break event/reservation/action。未知/不完整/冲突证据不生成成功；既有取消/断线/跨代与有界窗口、HMAC、队列、默认关闭和资源清理保持。
4. 不扩资源集、不改默认 MEDIUM、不加执行器、不放大 TTL/动作/重规划/等待预算。原 Python 任务准入合同继续有效；完整 Python 证据消费者以及 Life 正常装配等原 R3 剩余项仍须另行完成，不把本项兼容门禁冒充整个 G2/G1 PASS。
