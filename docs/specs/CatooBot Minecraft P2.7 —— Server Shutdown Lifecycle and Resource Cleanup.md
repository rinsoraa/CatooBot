# CatooBot Minecraft P2.7 —— 服务端退出生命周期与资源清理

制定日期：2026-10-18。状态：开工前归档。基线：`831929b7cb86f217c96e04adc82b6c738ed84ff9`。

## 1. 承接与目标

P2.6（历史任务 29）已证明所测 shadow 归因、预约超时原子性、同坐标跨维度负向与默认关闭。仍有明确缺口：启用模组后 Minecraft `stop` 保存世界，但 HTTP 19132 线程使 JVM 不退出；outbox 无显式所有权、停止和连接释放机制。

本任务在修改 Java 前，先完成旧规格命名与路径引用规范、归档本任务。收敛服务端启动/停止资源生命周期，使测试服正常停服后自然退出，端口可重新绑定，不依赖强杀进程。

## 2. 范围与架构边界

- 仅修改 `server_mod` 资源生命周期、账本清理、构建/测试接线及对应文档。
- 保持默认 `enabled=false`；关闭时不注册事件、HTTP 或 outbox。
- 模组仍是证据层，保持异步有界内存 outbox；不承诺断电持久化或停服必达。
- 不修改 TaskProposal → AgentPlan → TaskRuntime → Policy → AgentBridge → MinecraftService → Mineflayer 执行链，不启用 P3，不把 shadow 结论写入产品任务终态。
- 本轮只验收已固定的 Fabric dedicated server 1.21.1 / Loader 0.19.5 / API 0.116.17+1.21.1。集成服务器、其他版本兼容性未验证；N9-B 仍 BLOCKED，R1 不自动 PASS。

## 3. 实现契约

1. 对 HTTP server、HTTP 执行器、outbox worker 和正在使用的连接明确单一资源所有者。使用 Fabric 服务端生命周期事件启动及停止；重复停止安全，无资源时安全。
2. 在 SERVER_STOPPING 先关闭接纳门，取消待处理请求、清空主线程调度引用、使全部会话/预约失效。迟到排队或读取中的请求不得在停服后产生有效预约；旧服务端回调不能进入新一代资源。
3. 停止 HTTP listener 与执行器，释放投递连接，唤醒 outbox worker，采用有界等待；不得在服务器主线程无限等待网络、队列清空或尚需主线程才能完成的 HTTP 请求。
4. 停服策略为取消未投递队列，不尝试无限 flush；显式记录停服丢弃数量、失败及清理状态。队列中断、连接失败和非 2xx 仍按失败语义记录；所有连接在 finally 释放。
5. 端口绑定或工作线程启动失败必须关闭已创建资源，保持拒绝接纳，不留下局部可用的归因服务；不影响 Minecraft 正常运行及退出。
6. 新启用生命周期重新建立资源和空账本；旧请求、会话与积压不能跨代复用。默认关闭不产生生命周期资源。

## 4. 验收矩阵

### E1：纯 Java / 真实 HTTP 契约

- 正常启动/停止、重复停止、无启动停止、同进程端口重新绑定。
- 接纳关闭、排队请求和读取中停服无迟到预约；停服与成功提交竞争保持单一响应，已完成成功不被伪造为取消。
- 队列取消计数、worker 退出、HTTP executor 释放；投递异常/接收端挂起下有界停止。
- 启动绑定冲突回滚，随后正常启动；关闭门不能被迟到回调重新打开。
- 原 Booking/Dimension/RequestState/EventJson/ReserveBridge 回归。生命周期纯测试进入不依赖本机服务器的 Java CI。

### E2：真实 Fabric 服务器

先在停止状态备份测试服世界和配置，保存清单与哈希；只使用本轮测试身份、临时配置和影子接收器。

- 最终同一 JAR 连续至少两次 enabled 启动、正常 `stop`，每次等待原 Java 子进程 exit 0、记录停服耗时/世界保存日志、25565/19132 全部释放；同端口再次启动成功。不得用强杀替代通过。
- 最终 JAR 完成至少一次真实玩家登记→AFTER→接收端 SELF_CONFIRMED 的正向控制；此控制不冒充 P2.6 的 10/5/5 全量复验。
- 制造接收端不可用或挂起、outbox 有工作时停服，证明退出有界且失败/丢弃口径可审计。
- enabled=false 启动/停止，无 HTTP/outbox/归因监听，Minecraft 正常退出。
- 撤销临时 JAR、配置、身份和世界夹具，恢复所有备份原文件哈希，保留原始日志；最终服务器保持原先停止状态。
