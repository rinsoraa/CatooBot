## 1. 背景与本阶段要回答的问题

FU5 Follow-up 3 已将接受门改为“接受描述必须被许可词元表完整消费”，解决了一批含未知尾部、第二目标或无连接词动作的反例。但当前实现 `_consume_acceptance_phrase()` 是**最长优先的词元扫描器**：它检查每个字符是否能被词表消费，却不单独证明整句只有一个动作目标。

需要针对下列静态审计风险进行**可执行复现**，不能直接假设其一定会失败或一定会通过：

- `好，去砍橡木原木去砍橡木原木`
- `好，去砍橡木原木砍橡木原木`
- `好，去砍橡木原木去采集木头`
- `好，去砍橡木原木再砍橡木原木`
- `好，去砍橡木原木去挖原木`

其中前 3 条专门覆盖“全部字符可能由已许可词元解释、但包含重复动作/目标”的场景。第 4 条还可能触发现有“再 + 新目标”护栏，必须记录各机制单独与联合判定，不能只看最终结果。

**问题核心：** 完整消费是必要条件，但是否足以证明“单一意图”？不得让多个相容或重复目标，因为恰好只用了已知词元而被默认为单目标接受。

使用待决提案 `oak_log × 2`。如果某条消息的测试结果已被现有结构护栏正确拦截，也必须保留该证据；不得为制造缺陷而更改判定代码。

### 必须覆盖的分类

- **重复且相同的动作/目标**：未被标点、连接词或“再”隔开。
- **多个合法动作词连续出现**：所有词元都来自许可词表，但可能是第二个动作。
- **单动作 + 已审计收尾语**：如 `好，去砍橡木原木带回来`、`好，去砍橡木原木再回来`，必须继续合法。
- **单目标的冗余自然说法**：只纳入已存在的合法接受回归矩阵，不要扩大许可范围来追求“看起来更自然”。

## 4. 若反例成立：修复原则

将“词元全部可识别”升级为“整句符合一个受限的单目标描述结构”。优先考虑下列做法之一，选最少侵入的实现：

- 用现有解析器的目标跨度/动作跨度建立结构校验；或
- 让既有解析器暴露必要的 token/span 信息，再验证只有一个已审计目标结构；或
- 为该单一任务接受描述实现确定性、可审计的结构解析，并将物种、动作、单位与别名仍链接到既有词表。

不接受只用“动作词出现次数大于 1 就拒绝”作为未经论证的唯一修复：既有别名和动作词有前缀/重叠关系，合法短语必须先最长匹配并规范化；数量单位和收尾语也需按结构位置处理。

### 目标失败语义

- 冲突树种、明确数量冲突、新合成目标：维持当前 `NEW_GOAL` / 既有路由语义，不得被改成对旧提案的确认。
- 多个动作/目标、结构无法唯一解析、剩余文本无法证明属于单任务结构：`NOT_ACCEPT` → `handoff_compound_clarify`。
- 澄清时必须保留待决提案；不调用 `_accept_pending_handoff()`，不消费、不创建/推进任务、不执行任何资源或能力入口。
- 纯接受（`同意`、`可以`、`好，就按这个方案来`、`好的`）继续通过原有接受路径。

## 5. 自动化验收矩阵

对每个负向结构用例，必须同时驱动真实 `_route_turn()` 和真实 `_arbitrate_pending_handoff()`，不能只测 helper：

1. `accept_calls == []`。
2. 原待决提案仍在 `_pending_handoffs` 中。
3. 有 `handoff_compound_clarify`，返回非空澄清话术。
4. `wood_routes`、`delegate_calls`、`capability_calls` 全空。
5. `plans.calls == []`，无观察、规划、工具执行或 `action_id` 副作用。
6. 至少覆盖 `TASK_PROPOSAL`、`QUERY`、`ATOMIC_ACTION` 三种入口；不得出现跨决策类别绕过。
7. 复合输入澄清后，用户再发纯接受，提案仍可且只可消费一次。
8. 拒绝、取消、STOP/CANCEL、跨用户、跨 session、过期提案与双确认契约均无回归。
