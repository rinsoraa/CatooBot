## 1. 目标

让同一角色的生活状态、需求、开放目标、承诺、兴趣和既有经历产生有限游戏目标，并经新鲜事实、角色状态、能力/身份/风险/预算/冲突检查进入已有产品链。Life 只产生有来源和原因的候选，不执行工具、不授予权限。

## 2. 架构与范围

1. 审计并复用 `InitiativeContextAdapter / LifeIntentService → TaskProposalService → AgentPlanService / BoundedAgentPlanner → TaskRuntime → Policy → AgentBridge → MinecraftService`。不新增执行器、任务状态机、授权类型或平行重试循环。
2. LIFE 保持两道门：批准计划后才建待确认 Task，确认执行后才派发动作；USER 既有确认契约保持。角色意愿、模型输出、记忆、技能、提案或计划本身均不是授权。
3. 候选和计划必须保留 LifeIntent、来源事实/时间、proposal/plan、task/plan_hash/action 等关联。实时世界/背包、身份和必要角色状态未知或过期时，不伪装成可用事实；按实际前提补观察、澄清、暂停或拒绝。
4. 重新核验已有任务冲突、pending confirmation、睡眠/恢复/低精力及冷却去重的实际装配，不能只证明各模块的孤立测试。旧 LIFE 计划在批准、确认或重试时不得绕过当前必要事实与冲突门。
5. 有界性使用现有旋钮和冻结计划：默认 Task TTL 600 秒、最多 16 步、最多 2 次重规划、同参无进展 3 次上限；Life 默认 20 分钟冷却、每小时最多 3 条，提案每 pass 最多 3 条。探索的路径/步数/动作预算使用现有常量，不在测试里抬高或悄悄刷新预算。
6. 保持 `allow_medium=false` 默认值与工具白名单；本阶段正向以 SAFE 观察和 LOW 有界探索/移动为主，MEDIUM 默认拒绝必须取得零动作证据。通用采集、建造、战斗、交付和技能复用分别归后续 R3–R7，不能以 R2 代替。
7. 若实际装配缺少只读事实/角色/冲突检查，按最小范围补齐现有入口的安全门及回归；不让检查器创建或执行任务。

## 3. 门禁

### G1 — 产品契约与装配

- 真实持久化的开放 Goal/承诺/记忆信号至少覆盖两种来源，通过实际只读适配器、候选生成和门禁产生 LifeIntent；不能用直接构造最终 Task 冒充桥接。
- 提案/计划有来源、原因、期限、边界、风险和关联 ID；普通兴趣或不可执行目标允许只保留候选/澄清，不伪造可执行能力。
- 睡眠/恢复/低精力、必要状态缺失、世界/库存离线或过期、未知覆盖、目标不可行、身份未验证、工具/风险关闭、活跃任务或待确认冲突均有正反矩阵，缺事实不推测成功。
- 两道确认、归属/会话检查、并发/重复批准、过期批准/确认、重启和重规划预算；STOP/CANCEL 不等待模型，迟到或重复事件不得复活任务。
- 默认冷却、重复抑制、每小时/pass 上限和 TTL 可审计；确定性时钟/注入用例与真实自然经过的时间分开标明。

### G2 — 真实服务器与独立复核

按当前现场重新核验、正常保存停服并备份，测试结束恢复本轮当前世界/配置/模组并回到开工状态。仅使用授权测试服，夹具准备和真实产品动作分开。

- 至少一个 LIFE 来源的实际有界目标，走完整的 LifeIntent → TaskProposal → AgentPlan → 用户批准 → 待确认 Task → 用户确认 → 真实动作 → 真实终态；所有正向计划由现有 Planner 根据实际观察生成，不手写最终步骤替代。
- 批准前 Task 数量为零、动作/位置不变；批准后确认前仍零世界动作；正确确认后实际移动，服务端坐标及独立客户端复核结果。保留 actor/session/intent/proposal/plan/task/plan_hash/action 关联。
- 实际默认风险拒绝、重复/冷却、活跃任务冲突、必要前提缺失/过期与真实运行中 STOP/CANCEL 取得零额外动作或明确取消证据。不能以底层 API、纯规则函数或假执行器替代真实产品链。
- 生命周期和本轮回滚通过；测试 profile 不修改日常角色与凭据。若使用独立场景数据库，明确其用途，不伪称多场景重置为长时会话；长期角色与跨会话闭环仍归 R8。

### G3 — 真实 Provider、工程与发布

- 使用原配置的真实 Provider 核验自然目标/询问/拒绝/歧义/取消的类型化语义及安全路由，报告它与确定性候选/授权的边界；不能用固定模型文本或伪造动作结果充当语义证据。
- 如需 QQ，仍仅限杏仁罐头私聊和罐头商铺；本阶段不要求触达其他联系人。
- 如有代码变更，完成相关反例回归和最终全量 pytest、Node、ruff、format、mypy、Java、diff/凭据检查。未变部分的证据复用明确版本与哈希，不虚构新运行。
- 白名单同步至 CatooBot_github，提交前完整快照逐文件校验，保留无关历史差异，非强制发布并核验对应 CI 全部成功。
