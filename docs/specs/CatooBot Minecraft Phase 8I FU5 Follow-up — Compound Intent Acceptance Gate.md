# CatooBot Phase 8I FU5 Follow-up — Compound Intent Acceptance Gate

## 目标

修复 `handoff_target_verdict()` 对复合意图消息判断过宽的问题，避免一条消息包含与待决提案一致的采集描述、同时包含另一个独立意图时，仍消费旧提案。

已知反例：

当前待决提案为 `oak_log × 2`，输入：

- `好，去砍橡木原木并跟我走`

当前代码可能只检查木材目标与数量，然后接受旧提案，遗漏跟随意图。

## 不可违反的边界

- 不新增工具、权限、授权机制或平行任务状态机。
- 不修改 `ACTION_RISK`、`TOOL_ACTION`、`allow_medium`、Policy、双确认门、冻结计划与 `plan_hash`、STOP/CANCEL 权威路径及数据库 schema。
- 复用现有 `_arbitrate_pending_handoff()`、`handoff_target_verdict()`、`_pending_handoffs` 及原有采集/任务路由。
- 不允许通过删除测试或放宽断言获得通过。
- 不得把匹配的木材短语直接视为整条消息只有一个意图。

## 必测场景

1. 纯接受仍能消费当前提案一次。
2. `好，去砍橡木原木` 仍可接受 `oak_log × 2` 提案。
3. `好，去砍橡木原木并跟我走` 不得消费旧提案。
4. `好，去砍橡木原木，然后探索附近` 不得静默忽略额外意图。
5. `好，去砍五根白桦原木` 不得消费旧橡木提案。
6. `可以，不过这次砍五根橡木原木` 不得静默继承旧数量。
7. `好，给我做 64 块橡木木板` 不得消费旧采集提案。
8. 纯无关任务、询问、拒绝、无提案、跨用户及跨 session 的既有契约继续成立。

## 实现原则

优先采用确定性、保守的判定：只有消息可被无歧义地认定为纯接受表达，或单一且与待决提案相容的接受描述时，才能消费提案。

如果不能确认整条消息只有一个相容意图，则 fail closed：保留或按既有拒绝规则作废提案，并将消息交回自身路由或澄清。不得猜测用户愿意放弃额外意图。

不要仅靠增加关键词黑名单解决问题；先审计现有解析器能否可靠区分单一目标与复合意图，并为无法可靠判断的情形定义明确的保守行为。

## 验收门禁

- 在真实 `_route_turn()` 和 `_arbitrate_pending_handoff()` 上新增回归测试，不只测试纯函数。
- 断言待决提案状态、`_accept_pending_handoff()` 调用次数、资源入口收到的目标，以及是否有额外意图被吞掉。
- 原有纯接受、树种冲突、数量冲突和合成新目标测试全部保留。
- 运行相关 Phase 8I 回归、`pytest tests -q`、ruff、format、mypy、`git diff --check` 和 CI 两个 Job。
- 至少记录一次复合意图负向场景的运行证据；如使用桥接事件注入，必须明确标注，不得称为自然客户端交互。
- 检查受保护区域差异，确认没有借本轮修复改变权限或执行语义。
- 结束报告必须明确说明：复合意图被拒绝消费的证据、仍存在的解析边界，以及本阶段最终裁决。

在复合意图反例通过前，不得将该缺口描述为“已验证不存在”。
