# CatooBot Minecraft R3 —— Collection Evidence Chain Counterexamples and Cross-Generation Closure

开工前归档：2026-10-20。前置检查点为 [R3 Python 采集证据消费者与恢复边界](../MINECRAFT_R3_CONSUMER_REPORT.md)（本项在其之后、仍属 R3，不减少原 G1–G4、R4–R8、Integrated/LAN 与长期 Life/Play/Learning 验收）。开发目录保留全部未发布修改，发布基线仍为 `d121127ef5b78016430c56a6c3f15f9d2a4cb6a4`。

## 问题与合同

上一检查点已让 Python 纯消费者在派发前与终态生效，并用 24 条真实归一化记录 + 62 条注入反例证明"字段级错配不可通过"。G2 仍要求**跨代、重放、乱序、竞争**在真实任务运行时上同样不可拼接成功，且 Node 侧"全链消费者"要有明确清点。当前待收口缺口：

1. **跨代（replan）**：计划被重规划后，旧版本计划的 dig 证据/旧 pickup 结果不得为新计划提供成功；旧版本的"已验证"结论不得跳过新版本的复核。
2. **恢复（restart/resume）**：恢复后的任务必须重新用持久化证据复核；跨 runtime 实例的旧证据不得结算当前步骤。
3. **重放/重复**：重复或迟到的 dig/pickup 终态事件不得二次结算，同一服务端掉落不得贡献两次。
4. **乱序/竞争**：pickup 通知先于 dig 证据落盘、取消/过期与 pickup 结算竞争时，都不得产生"完整成功"或复活终态。
5. **Node 全链清点**：当前源码只有 `minecraft_runtime/strict_attribution.js` 消费 `server_proof/server_collection`；须审计确认没有第二个消费者，并把每条拒绝分支（12 ID 掉落映射、booking、break 关联、协议降级、缺失/未知版本）的断言纳入可复核清单，若发现缺口在同一契约内补齐。

## 实施合同（编号）

1. 消费者与运行时都不得从库存、历史成功标签、附近实体或模型输出倒推采集来源；跨代、跨实例、跨连接的证据一律不得拼接为成功。
2. 恢复路径必须对持久化证据**重放**纯消费者；旧的"验证成功"缓存只作审计，不得跳过复核。
3. 事件重放、乱序与生命周期竞争只在既有语义内收敛：终态不可复活、不自动重发世界动作、不增加预算；无法判定时保持明确非成功。
4. Node 侧只承担同一契约的消费与拒绝，不新增执行器、表、迁移或权限；默认关闭语义不变。
5. 不抬高 TTL（600 秒）、最多 16 步、2 次重规划、同参无进展 3 次、动作/等待/距离上限；不改 P3 原子破坏、探索、合成与取消/过期/授权语义。
6. 本项为**离线确定性**任务：不启动/重启日常 Bot、Bridge、测试服，不部署 JAR，不发 QQ 消息，不操作世界；真实服务器矩阵与到达门禁留给后续 G3/G4 任务。

## 本项必需门禁

- **G2-a 跨代隔离**：真实 TaskRuntime 上完成一次采集 dig 后重规划到新计划，断言旧证据不满足新计划的 pickup/终态；旧版本验证结论不被采信；零后续世界动作。
- **G2-b 恢复重放**：以真实 SQLite 持久化记录（含 `collection_verification` 旧缓存与真实 dig/pickup 证据）恢复运行时，断言复核结论由当前证据重新计算；被篡改的持久化证据在恢复后仍判非成功；技能与记忆不产生伪成功。
- **G2-c 重放/重复/乱序**：重复与迟到的 dig/pickup 终态事件、pickup 通知早于 dig 证据落盘、取消/过期与 pickup 结算竞争——每类至少一条确定性用例，断言只结算一次、终态不复活、无额外派发。
- **G2-d 消费者一致性**：上述运行期用例全部复用同一个纯消费者（不得出现第二套判定），并有结构性断言（例如只允许一个模块导出该判定）。
- **G2-e Node 全链清点**：`npm test` 全绿；同一份清单列明 `server_proof/server_collection` 的消费点与每类拒绝；若补充断言，不得弱化既有严格归因 84/84。
- **G2-f 工程门禁**：完整 `pytest`、`ruff check`、`ruff format --check`、`mypy app` 全绿；保留首次失败与修复范围。
- **G2-g 归档**：改前源码/清单/规格散列先存入新证据目录；结束输出脱敏报告与证据 JSON，更新 ROADMAP、docs/README、CHANGELOG；Node/Java 若字节未变则逐文件核对后复用协议检查点证据，变化则重验对应门禁。

本项通过只关闭 G2 中的"全链反例与跨代/恢复收口"子项；R3 的 G1（正常 Life/Goal/Memory 与真实用户通道装配）、G3（真实服务器逐 ID 矩阵）与 G4（真实 QQ、发布与 CI）继续保留，原 G1–G4 全 PASS 后才可进入 R4。
