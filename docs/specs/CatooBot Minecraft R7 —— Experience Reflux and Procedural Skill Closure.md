# CatooBot Minecraft R7 —— Experience Reflux and Procedural Skill Closure

开工归档：2026-10-22。验收完成：2026-10-22，R7 真实矩阵 5/5 PASS、81 项技能测试通过；生产代码自 R6 未变。

## 1. 目标

把真实成功/失败的经历转成**有来源**的技能候选，经适用性判断后在受控范围内复现，并保留来源、证据与失败边界；不把聊天自述、模型猜测或旧计划当成学习。

首期支持：

- 经历来源：真实 TaskRuntime/服务端证据（成功任务、失败原因、世界恢复、用户确认）；
- 技能候选必须绑定来源 episode/task/evidence/version，不能无来源生成；
- 技能检索必须做适用性判断：服务器/维度/资源/工具/目标/风险等级不匹配 → 不使用；
- 复现必须仍走既有 TaskProposal → TaskRuntime → Policy → 确认 → 服务端核验链，不新增第二执行器；
- 失败/部分成功/未知不得被写成成功技能；冲突来源进入候选/拒绝，不静默覆盖；
- 首期只支持已有有界技能（采集/放置/战斗/交付）的参数化复现，不生成任意代码/脚本。

## 2. 门禁

### R7-A1 经历与来源

- 从真实成功/失败任务生成候选，记录 task_id、plan_hash、evidence、版本、时间、维度、角色/会话；
- 没有真实证据时不得生成候选；
- 不把聊天回复、动作自述或未核验结果作为学习来源。

### R7-A2 技能候选与冲突

- 候选去重/版本化；同来源重复不重复计数；
- 冲突/低置信/被撤销的候选不得自动成为 ACTIVE；
- 明确 ACTIVE/CANDIDATE/REVOKED 状态与审计记录。

### R7-A3 适用性判断

- 检索时校验服务器、维度、资源族、目标、工具、风险与角色状态；
- 不适用时回退到确定性规划，不静默套用旧技能；
- 技能只能提供计划候选，不能绕过授权/确认/预算。

### R7-A4 受控复现

- 在新任务中复现一次，必须重新观察当前世界并重新确认；
- 复现结果由服务端/任务证据独立核验；
- 失败/环境变化时停止，不自动重试升级或扩大范围；
- 技能不能引入未批准工具、无限循环或超出原任务上限。

### R7-A5 真实服务器矩阵

正常 Bot.start、隔离 SQLite、公开测试 Bible：

1. 一次真实成功采集/放置/战斗/交付 → 生成有来源候选；
2. 候选在相似但不同的目标上检索/复现，结果真实核验；
3. 维度/资源/工具/风险不匹配 → 不适用回退；
4. 失败/部分成功/未知不生成成功技能；
5. 冲突/撤销候选不被使用；
6. STOP/CANCEL、超时、重启后不出现假技能成功；
7. 测试结束恢复本轮新快照并逐文件哈希核对。

### R7-A6 工程与发布

- 确定性测试、完整 pytest、Node 单元/E2E、Java（如字节变更）、ruff/format/mypy；
- 正式 R7 报告、脱敏证据、白名单同步、提交、推送、CI 三 job success；
- 任一 gate 未 PASS 不进入 R8。

## 3. 出口

R7-A1–A6 全部 PASS 后，才可制定 R8 任务书。R8 端到端长期角色验收不在本阶段。
