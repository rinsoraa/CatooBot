制定日期：2026-10-19。开工前归档。基线：`ddb4eb44f417c0483903dea7771cd90e2cea610c`。

## 1. 目标与授权来源

用户已明确授权持续完成 Rx v3.0 剩余任务直至 R8，并授权本机测试服务器的配置和门禁实验。本任务据此推进路线规定的 P3；历史设计中的“等待独立批准”描述当时授权边界，不据此重复请求已有授权。

P2.6 已完成影子匹配矩阵，P2.7 已完成专用服务器资源退出。当前产品 dig 仍可能仅凭客户端观察到方块消失而成功；N9-B 仍 BLOCKED。P3 必须使严格模式中的成功依赖唯一可信服务端破坏事件，完成真实 TaskRuntime 执行窗口复验；不能只升级影子状态标签或测试桩。

## 2. 实现范围与不变量

1. 通过现有 Minecraft 配置与 runtime 环境显式启用严格归因；默认关闭。密钥只从私有环境/配置注入，不通过工具参数、模型、公开 API 返回或日志泄露。
2. 保留 TaskProposal → AgentPlan → TaskRuntime → Policy → AgentBridge → MinecraftService → Mineflayer；不新增执行器、授权或任务状态机。已有 MEDIUM、双确认、工具/区域/数量预算不变。
3. dig 真正派发前取得服务端当前连接的 session_ref、服务端 UUID、维度和目标登记回执。登记失败、响应不确定、身份/维度/目标不符时零挖掘包；取消后即使回执迟到也不得启动 dig。
4. 模组签名事件由 runtime 的独立归因入口验证，再与当前动作的 reservation_id、action_id、session_ref/seq、实际玩家 UUID、维度、整数坐标和方块前态逐项匹配。只匹配可信唯一事件；同一事件仅消费一次。
5. 不比较跨进程单调时钟。由服务端 TTL、每次连接会话、runtime 实例动作 ID 与客户端自身有界等待实现因果关联和迟到隔离。
6. 严格模式中，仅 SELF_CONFIRMED 且目标真实移除才允许 dig 成功。事件缺失、推送故障、外部移除、他人破坏、冲突、过期、通道重启或认证失败均保留 UNKNOWN/明确非成功，绝不退回 SELF_INFERRED 成功。
7. STOP/CANCEL/TIMEOUT/断线保持既有终态权威，释放等待器和本次关联记录；迟到/重复事件不能复活动作或任务。重新连接/服务端重启前的会话与登记不得复用。
8. 证据 payload 明确 server_block_break 来源、schema 及事件关联字段。Python 消费者仅在完整且严格绑定当前步骤时识别新证据；历史时序推断仍被拒绝。破坏归因与掉落、拾取、库存净增独立核验，不自动制造技能或资源成功。
9. 为本轮新增协议和活动关联状态设定体积/数量边界，过载拒绝；不因缓存清理而接受当前会话的 nonce 重放。清理失效/过期预约与断开会话引用，保留失败计数。原 shadow 接收器保持仅诊断职责。

## 3. 真实与确定性门禁

### G1：Node / Python / Java 契约

- 正常登记、签名事件与唯一消费；事件先于登记回执、回执丢失、登记失败和取消期间回执到达。
- 错误签名、缺字段、错误类型、错误 action/reservation/session/UUID/维度/坐标/方块、未知 schema、超大消息必须拒绝。
- 事件缺失、重复、冲突、迟到、旧 runtime/会话、服务器重启、TTL、STOP/CANCEL/TIMEOUT 竞争；终态唯一，无取消后的 dig 派发。
- 默认关闭保持既有行为及测试；严格启用而密钥/通道不可用时不得静默降级。
- Python 新证据严格字段校验、任务步骤 action/target 绑定、记忆和技能消费边界；旧正确证据不回退，旧过宽证据仍拒绝。
- 全部原 Java、Node 与 Python 相关回归。新增测试必须穿过实际集成函数，不仅自测新辅助类。
