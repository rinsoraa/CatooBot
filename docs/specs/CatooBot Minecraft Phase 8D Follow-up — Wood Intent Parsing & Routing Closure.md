## 已确认的三个缺口

1. `WOOD_SPECIES` 子串匹配导致 `深色橡木`、`暗橡`、`dark_oak`、`dark oak` 同时命中 oak 与 dark oak，错误产生 `ambiguous_species`。
2. `_wood_preempts()` 对 `wood.problem` 的处理过度依赖礼貌性请求标记，导致某些明确的竹子请求或多树种歧义请求绕过木材入口，回落到旧单目标资源路径或普通角色路径。
3. `_parse_log_count()` 的 `\d{1,2}` 会把三位数数量的末尾两位当成完整请求。例如 `100根` 会被解析成 1，`102根` 会被解析成 2，且不会触发上限说明；`0根` 也会被静默转换成 1。

## 修复要求

### A. 树种解析

- 保留现有六种原木支持矩阵与确定性解析，不增加 LLM 调用。
- 修复别名冲突，使精确或最长匹配能够正确识别深色橡木，不再把其专属别名误判为橡木。
- 对真正的多树种请求仍须明确澄清，不允许随意选一个树种。
- 为六种原木分别补充解析测试，并针对深色橡木的全部别名增加回归测试。

### B. 唯一接管

- 重新审查 `_wood_preempts()` 对 `wood.problem` 的分支。
- 明确区分普通叙述、查询、否定表达与真正的行动指令。
- 对明确请求采集但目标不支持或树种歧义的消息，必须得到稳定的 `BLOCKED` 或 `CLARIFY` 结果，不得静默落回旧单目标路径或普通工具链。
- 普通聊天、纯查询、确认/取消/暂停/继续、状态查询、已有活动任务及 `busy` 语义保持不变。
- 添加以下回归案例：
  - `去砍两根竹子带回来` → 明确拒绝，不进入旧资源模板。
  - `去砍两根橡木和云杉原木带回来` → 明确澄清，不得自动选择橡木。
  - `我昨天砍了两根竹子` → 保持普通叙述语义。
  - 含礼貌性请求词的既有案例继续通过。
- 在代表性不支持与歧义输入上直接断言 `plan_resource_task()` 未被调用，同时验证不发生工具执行。
- 保留 `allow_medium=False` 的规划期策略阻断，不允许新分支绕过 `_plan_wood()` / `_policy_blocked()`。

### C. 数量解析

- 解析完整的整数 token，确保三位数或更长数字不会只取末尾一到两位。
- 任何大于 `WOOD_MAX_TARGETS` 的数值都必须设置超限标记，并在确认前明确显示该计划实际采集数量及本期上限；不得静默缩小并声称完成原请求。
- `0根` 应得到明确拒绝或澄清，不得转为 1 根任务。
- 覆盖 `0、1、2、3、10、99、100、102` 等边界数量，并覆盖对应单位和中文数字。
- 保持实际规划不超过 2 个目标，且不扩大任务步骤或动作预算。
