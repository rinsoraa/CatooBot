# CatooBot Phase 7F.1 — Bounded Autonomous Exploration

## 一、项目基线与产品目标

仓库：`rinsoraa/CatooBot`

当前已知基线：Phase 7D.3  
参考提交：`a267afe77bbc65f93d8b753f8e57188d9da911c0`

先核对当前工作区 `HEAD`、`main`、`origin/main`、实际工作目录，以及未提交变更。不要假设当前工作区一定等于上述提交。

产品定义以仓库 `docs/specs/CatooBot_Phase7E_技能学习与程序性记忆_VibeCode任务书.md` 为准。

罐头不是 Minecraft 自动化采集工具，也不是只能等待 QQ 命令的机器人。她应当是能够持续生活、形成自身意图、真实进入 Minecraft 世界游玩、与玩家互动并从经历中积累方法的 AI 角色。

本阶段只实现第一个最小自主游玩闭环：**有界自主探索**。

## 四、本阶段的具体目标

建立以下完整链路：

真实角色状态 / 合格 LifeIntent  
→ 有界探索提案  
→ 既有 AgentPlan 与能力、前置条件校验  
→ 既有批准和确认门  
→ 既有 TaskRuntime  
→ 已注册的安全观察及导航工具  
→ 真实 Minecraft 结果验证  
→ 可追溯经历和后续生活规划。

### 4.1 探索范围

- 选择一个可明确描述、能够通过现有工具验证的简单探索目标。
- 目标只能来自当前真实可观察的世界事实或已验证的持久记忆。
- 使用现有 SAFE 观察能力，按需选择有限的导航目标。
- 使用现有 MOVE、LOOK、STOP 等能力时，必须重新审计当前工具名称、参数 schema、风险分类、授权要求和动作状态语义，以实际注册表为准。
- 为探索设置有界的动作数、活动时长、空间范围和失败退出条件；尽量复用现有预算，不新增一批重复配置旋钮。
- 行动途中遇到玩家离线、世界变化、目标失效、路径失败或超时，应依既有规则停止、取消或安全结束。
- 任务成功必须由真实执行结果与相应后置条件判定，不得由 LLM 自述、计划完成或动作调用返回成功来代替。

### 4.2 必须保持的安全约束

- LifeIntent 不得直接调用 Minecraft 工具或 ActionRuntime。
- TaskProposal 与 AgentPlan 不等于真实执行。
- 继续复用现有 TaskRuntime、Policy、能力目录、身份校验、TaskAuthorization、TaskStepAuthorization 及确认流程。
- 保持 LIFE 任务已有的批准计划与执行确认两道门。
- `allow_medium=false`、19 个注册工具、现有风险分类、任务状态、停止与恢复语义均不得被隐式修改。
- 第一版不新增自动挖掘、放置、攻击、合成、容器操作或其他世界修改行为。
- 不新增任意代码执行、不构建无界 LLM 工具循环、不允许技能直接执行。
- 不得以关闭安全门、降低归因要求或放宽旧断言换取测试通过。

如果现有权限策略不允许某个 LIFE 探索步骤执行，必须返回可解释的阻止原因。不得自行授予新权限。

### 4.3 经历、记忆与角色连续性

- 区分计划、真实行动、真实观察结果和历史记忆。
- 所有新写入的 Minecraft 经历必须保留实际来源、服务器范围、任务或步骤引用、时间和相应的证据等级。
- 只有通过当前身份验证的玩家关联才能用于对应的身份相关行为。
- 未能验证的观察只能保存为相应的不确定事实；不能被写成已确认的亲身经历。
- 不保存思维链，不复制完整世界快照或非必要的原始 Task payload。
- 优先复用现有 MinecraftMemoryBridge、身份桥和技能体系，不建立第二套记忆系统。

## 五、测试与验收门禁

### 单元与集成

覆盖：

1. 无合格意图时不创建任务。
2. LifeIntent 只生成提案或计划候选，不直接执行。
3. 未批准、未确认的 LIFE 任务不能执行。
4. 合法的探索任务能够复用既有 TaskRuntime 和注册工具。
5. 导航成功、导航失败、目标不可达、世界变化、玩家离线、超时、用户取消和停止。
6. 动作数、探索范围和活动时长均受硬预算约束。
7. 重复事件、事件重放和进程重启不会重复执行已结算步骤或重复记忆。
8. 观察证据不足时不能伪造成功经历。
9. InMemory 与 SQLite 的行为一致，真实迁移可幂等升级。
10. 不存在绕过 Policy、确认门、授权校验或停止机制的路径。

### 真实 Minecraft 门禁

必须使用真实 Java 服务器验证新的端到端行为，至少覆盖：

- 正常探索与导航，且结果由真实世界状态确认。
- 路径受阻、目标失效或世界变化时的安全停止。
- 用户停止/取消之后不继续产生新动作。
- 任务结束后，记录的经历与实际执行结果一致。
- 正常结束及异常结束均不会留下持续移动或未清理动作。

若真实环境门禁无法执行，明确标记 `SKIPPED` 并列出原因，不得宣称 PASS。

### 全量门禁

按项目既定纪律串行运行 ruff、format、mypy、全量 pytest、WebUI typecheck/Vitest/build、浏览器 E2E、Minecraft Node 单测和 E2E、数据库迁移与一致性检查、真实服务器门禁及 CI。

不得并发运行项目要求串行的重型门禁；不得放宽既有断言。
