## 实施与验收

1. 产品计划中的拾取实体必须引用该次 dig 的签名 collection 结果，并绑定其 break action；附近列表顺序、旧同类物品或另一采集动作不能替代来源。缺少任一证明时零拾取派发。
2. 在服务、HTTP runtime、签名预约和接收端完整传递并核验关联；异步预约完成后重查连接、维度、实体、取消，不复用失效前提。签名错误、串号、乱序、重复、冲突及超时均不能生成完整成功。
3. 统一木材和通用资源的白名单、数量、新鲜度、工具/耐久与危险合同，规划及真正世界动作前复核；空手为明确状态，不能以省略 expected_tool 表示冻结空手。继续使用既有执行器、确认、权限、TTL 和动作预算。
4. 调查并修复精确游戏钩子的实际行为和夹具问题。每次运行采用新证据目录，保留原始失败；命令准备、直接 HTTP 探针与真实 Planner/TaskRuntime 产品链明确分开。
5. 原 R3 的 12 ID、两种库存基线、拒绝/工具不足/危险/路径失败/目标变化/掉落拾取不明/净增不足/执行中取消矩阵全部保留。单个橡木探针成功不能成为阶段出口。
6. 最终源码冻结后执行完整 Python、Node/E2E、Java/Fabric、静态检查及真实生命周期；重新核验受限 QQ 会话与 Provider 门禁，按本轮备份恢复现场，白名单发布与核验对应 CI，生成 COMPLETE 回执。
