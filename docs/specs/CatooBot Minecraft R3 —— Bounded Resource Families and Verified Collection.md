## 1. 目标与冻结支持集

从既有木材垂直闭环扩展为统一、逐资源声明合同的有界采集。成功须分别证明目标破坏、目标掉落生成、同一角色拾取及库存净增；任何一段未知都不能拼接成成功。复用现有计划、授权、任务状态机与原子动作，不建立第二执行链。

本阶段至少覆盖当前已暴露的 12 个目标 ID；发现其他当前可执行的资源入口时，必须一并纳入合同或明确拒绝并记录，不能绕过统一校验。

| 资源类 | 目标方块 | 预期物品 | 数量与必要工具 |
|---|---|---|---|
| 树干原木 | oak/spruce/birch/jungle/acacia/dark_oak_log，分别独立验收 | 同种 log | 保留每任务最多 2 根、同列相邻合同；可徒手，若绑定工具仍核验工具身份与预算 |
| 石材 | stone、cobblestone，分别独立验收 | cobblestone | 每任务最多 1 块；依据当前 1.21.1 实际采收元数据检查合适镐与耐久，不以 canDigBlock 代替可获得掉落 |

绯红/诡异菌柄、去皮木、木板、树叶、深板岩矿、附魔改变掉落的工具、液体、危险方块及未知资源不能被静默映射为以上资源；未验证能力返回明确 UNSUPPORTED/UNKNOWN/前提拒绝。若后续扩大支持集，先补同一规格的合同和门禁，不能只加别名。

## 2. 实施合同

1. 审计并统一 QQ/游戏内 USER、LIFE、技能建议、重规划以及直接资源模板入口的资源解释；询问、否定、歧义、未知种类和超预算数量不建可执行计划或进入明确澄清。模型、记忆和技能不能补造资源、目标坐标、工具事实或授权。
2. 目标白名单、预期掉落、数量、观察新鲜度/覆盖、工具及耐久、交互距离、导航、单动作与任务时长均可审计。保留 Task TTL 600 秒、最多 16 步、最多 2 次重规划、同参无进展上限 3；不得为通过测试抬高默认预算。工具若可换，必须作为冻结计划里的显式授权步骤，不暗中装备/制造工具。
3. SAFE 观察取得真实目标、世界、库存和工具事实。必要事实缺失、过期、覆盖不足或无法读取时拒绝/澄清，不将空白或默认值解释为已满足。规划后与派发前再次核对目标、维度、当前工具、耐久及危险前提；异步等待后重查取消与授权，不能使用已失效的检查结果。
4. 逐资源处理脚下/支撑方块、坑洞边缘、坠落、相邻液体、上方重力块、洞穴/封闭路径和目标消失。路径失败不能通过额外破坏/放置绕路；R4 能力不得借采集引入。对无法确认安全的场景保守拒绝，不能称作已安全处理。
5. 明确区分“可破坏”和“可采收”。工具采收等级、物品身份与剩余耐久必须来自锁定版本的实际数据/运行时事实，注明来源；缺少耐久或附魔信息时不猜。工具不足/坏工具/不支持的掉落变体取得零破坏证据。
6. 成功破坏继续使用 P3 的严格服务端归因，关联实际 actor/session/action/reservation/维度/方块；严格证据不可用、验签失败或回执不确定时不得以推断性 SELF_INFERRED 成功替代。服务端模组存在本身不证明执行成功。
7. 掉落实体须与这次已确认破坏建立可验证关联，拾取须绑定同一实体与实际采集者，最终再比较可信库存基线与结束快照。相同物品的旧掉落、其他玩家破坏/丢出、并发生成、实体 ID 复用、合并/消失、目标被他人拾取、包丢失/重复/迟到均不能靠时间或距离猜为本任务贡献。现有合同不足时扩展同一证据协议与服务端模组；保留有界输入、签名、队列、幂等、生命周期与兼容拒绝语义。
8. `allow_medium=false` 生产默认保持；正向测试只在明确授权的独立测试 profile 启用 MEDIUM 与严格证据，不写入日常配置。USER 原有确认和 LIFE 两道门、归属/会话、当前角色/任务冲突及 STOP 优先合同继续成立。成功与未知/失败分开，取消、断线、过期及迟到事件不能复活任务。

## 3. 门禁

### G1 — 逐资源合同、意图与事实

- 冻结支持集有完整表与统一实现，逐 ID 验证工具/等级/耐久/数量/掉落/危险条件。现有接口的未知资源、模糊木种和派生物不静默回退。
- 所有正常装配入口都经过同一事实与风险合同；真实 Provider 的行动、询问、否定、歧义和停止语义配合确定性路由验证，非行动回合零采集执行。
- 默认权限、双确认、重复/并发、身份隔离、过期、重规划与无进展预算全部回归；LIFE 与记忆不能增加权限。

### G2 — 独立证据与协议反例

- 分别验证 BREAK_CONFIRMED、目标 drop、目标 pickup、inventory delta；不把其中一项当其他项的替代。每段缺失、混淆、重放、乱序、另一 actor/session、旧实体/ID 复用均不能得到完整成功。
- 服务端证据若变更，完成旧/新协议兼容、默认关闭、签名/输入边界、队列与超时竞争、取消/断线/跨代、正常保存退出和资源清理门禁；不能只运行纯规则用例。
- 真实库存净增与独立服务端库存快照核对，正向同时包含初始库存为零和已有同类物品的情形，证明比较的是增量。

### G3 — 真实服务器逐 ID 矩阵

本轮重新核对现场，正常保存停服后制作新的当前世界/配置备份；不复用 R2 的旧世界快照覆盖之后状态。测试结束逐文件恢复、移除本轮实验文件并恢复开工运行状态。

对支持集的每个目标 ID 取得独立记录：

1. 至少两条完整正向 Task，由正常 Planner 根据实际观察生成步骤，真实批准/确认后运行；分别覆盖零基线和已有同类库存。保留目标、工具与耐久、actor/session、plan_hash、action、服务端破坏、drop/pickup 实体和前后库存关联。
2. 默认风险关闭、目标未知/失效、必要事实缺失/过期、工具/耐久不满足、路径失败、资源特有危险均有真实拒绝或明确非成功记录。徒手可采的资源明确记录“无工具合法”，另外验证错误的显式工具绑定，不能伪称所有资源都必须有工具。
3. 独立干预 drop/拾取确认缺失、旧同类掉落/其他玩家干扰和库存不净增，结果保持 UNKNOWN 或既有非成功状态；不自动换目标、换工具或引入额外世界动作绕过失败。
4. 每个目标 ID 有实际执行窗口中的 STOP/CANCEL 记录；服务端/独立观察者证明已经行动，再确认停止、唯一终态、延后不再执行与不复活。清晰记录停止瞬间物理收敛；保存两次晚期坐标，不能只保留断言。
5. 准备命令与产品动作分开；RCON/独立非 OP 观察者仅复核和夹具控制，不伪装产品采集。观察轨迹在恢复等待后、动作窗口前重新开始并有界保存，避免缓冲被等待阶段占满。
