## 三、P0：修复木材关键词闸，改为语义决策主导

这是本轮最高优先级。

```text

    ↓

    ↓

    └── _wood_route
    ↓
_route_turn
```

这会导致包含木材关键词的输入在九类通用决策路由之前被截获。

必须将生产路由调整为：

```text
用户消息
    ↓
现有 STOP/CANCEL 控制优先处理
    ↓
构造当前可信上下文
    ↓
统一 LLM 决策
    ↓
严格校验 TurnDecision
    ↓
根据决策类别分流
    ├── CHAT / NARRATION
    ├── QUERY
    ├── ATOMIC_ACTION
    ├── TASK_PROPOSAL
    ├── CLARIFY
    ├── UNSUPPORTED
    ├── CANCEL
    └── STOP
```

具体要求：

1. 删除 `mentions_wood(message)` 作为通用主分流闸的行为。
2. `CHAT`、`NARRATION`、`QUERY` 和其他非任务类别，即使包含木材关键词，也必须遵从已经校验的决策类别。

4. 明确的木材任务必须保留既有 `_wood_route`、参数验证、计划生成、授权及后置验证。
5. 否定、歧义或非法木材目标只能被拒绝或要求澄清，绝不能被提升为可执行请求。
6. 模型未能解析或校验失败时，只能进入安全失败路径，不能再回落到普通 `NORMAL` 模式并重新开放 Agent/Tool 路由。
7. 不得以新增关键词、正则表达式或新的木材专用分类器取代统一 LLM 决策。

特别注意：`mentions_wood` 等现有代码如果仍有必要，可以在已经判定为 `TASK_PROPOSAL` 的分支中作为辅助检查或安全否决条件使用，但不能重新成为所有消息的入口闸门。

### 非木材任务的强制约束

## 五、P1：完成九类决策的真实路由

根据现有实际接口逐项接线并测试。

### CHAT / NARRATION

继续使用逐回合 `CharacterTurnMode.CHAT_ONLY`。

断言：

- Agent 不执行；
- ToolOrchestrator 不执行；
- 不创建任务；
- 不产生非预期 `action_id`；
- 工具调用型 JSON 不会被当成执行结果。

### QUERY

仅允许进入经审计的只读能力。

必须完成至少一个真实世界查询闭环：

```text
用户查询
→ LLM 决策
→ 已审计只读工具
→ Minecraft Service 返回真实查询结果
→ 角色依据结果回复
```

并完成至少一个真实背包查询闭环，证明回复中的物品信息来自实际工具返回值，而非模型猜测。

不得仅测试决策器输出了 `QUERY`，就声称查询闭环通过。

查询后用于回复的 LLM 调用必须继续处于 `CHAT_ONLY`，不能因回复阶段再次触发工具执行。

如果现有只读能力无法取得所需数据，必须记录具体阻塞原因，不能伪造真机结果。

### ATOMIC_ACTION

只允许调用当前已经注册、开启、通过白名单审计且满足现有策略条件的能力。

必须通过现有工具执行、Policy、身份、授权和 Action Runtime 相关路径。不得为了快速接线而直接操作 Mineflayer 或调用绕开授权的底层 Service 方法。

### TASK_PROPOSAL

只有当前规划器真实支持的任务才能进入计划链。

木材正向任务必须保留既有校验与授权机制。其他目标必须先审查能力支持情况，不得以通用任务入口代替能力验证。

已识别目标但无法建立计划时，不能静默返回 `None` 并回落到普通角色 Agent/Tool 路径。保留既有 `plan_service_unavailable` 等错误语义。

### CLARIFY / UNSUPPORTED

使用安全回复，不产生任务或世界动作。

### CANCEL / STOP

先沿现有控制路径发出取消或停止，再完成与本条消息关联的决策记录。模型返回不能撤销已经发出的控制，也不能在同一回合重新启动动作。

**不得简单返回模糊的 `None`**：必须确认外层 `_reply()` 不会将其解释为“未处理”，进而调用 `respond(NORMAL)`。应使用明确的已处理结果或 `_TurnReply(None, CharacterTurnMode.CHAT_ONLY)` 等符合当前实际控制流的形式。

具体返回方式必须依据真实调用链决定。

新增或扩展测试，至少覆盖：

- 工具离线和世界观察失败有明确结果；
- 上下文组装异常不产生世界动作；
- 上下文内容和异常正文不会进入敏感日志。

### 必须覆盖的语义矩阵

至少加入以下场景：

1. “这棵树真高啊” → 聊天/叙述，不建木材任务。
2. “帮我砍 8 个橡木原木” → 正向木材任务链。
3. “不要砍树” → 不创建木材任务。
4. “木头不够了” → 根据真实上下文澄清或回复，不默认采集。
5. “继续刚才的工作” → 使用真实活动任务状态，无法确认则澄清。
6. 查询附近方块 → 真实只读结果驱动回复。
7. 查询背包数量 → 真实背包返回值驱动回复。
8. 世界数据过期 → 刷新或明确无法确认。
9. 玩家身份不明确 → 不猜目标，不执行玩家相关动作。
10. 工具关闭或服务器离线 → 不执行、不编造结果。
11. 非法决策输出 → 安全失败。
12. 普通聊天包含工具调用 JSON → 零世界动作。
13. STOP/CANCEL 与其他行动诉求冲突 → 控制优先。
14. 未支持的放置和攻击请求 → 不调用相应动作。
15. 并发聊天和行动请求 → 状态隔离。
16. 已识别的任务目标无法创建计划 → 不回落到 Agent 执行。
17. LLM 将否定木材输入误分类成 `TASK_PROPOSAL` → 后续确定性安全约束仍能阻止执行。

所有零副作用用例都要使用真实调用计数器、Spy、动作追踪或等价强证据，不得仅凭最终回复判断未发生调用。
