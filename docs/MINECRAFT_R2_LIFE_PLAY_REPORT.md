## 实施范围

复用现有 `InitiativeContextAdapter / LifeIntentService → TaskProposalService → AgentPlanService / BoundedAgentPlanner → TaskRuntime → Policy → AgentBridge → MinecraftService`。Life 仍只产生意图与候选；批准计划才建立待确认 Task，正确用户与会话确认后才授予执行权限。

- 规划、批准及 LIFE Task 每次外部派发前，通过同一只读门禁核验真实来源、角色归属、意图状态/期限、持久化精力、睡眠/静默/恢复状态、任务冲突和在线世界。检查异常或超时拒绝；STOP 不受该检查阻塞。
- 角色准入读取实际数据库记录；缺失、损坏或非法精力值不借用聊天通路的默认健康状态。普通聊天的既有容错语义保留。
- 直接查询 runtime 当前连接，失败时不使用旧镜像作为在线证明。近场观察年龄上限 5 秒，观察时间还须属于当前连接（同机时钟容差 0.5 秒）。旧 LIFE 计划不能靠重试跳过当前状态。
- 全局当前任务改为读取持久化未终态记录，避免被最近二十条终态历史挤出。准入另外检查未结算的外部派发；任务状态读失败传递 `UNKNOWN`。
- 启动、睡眠、静默、冲突等可逆阻碍解除后，同一时间桶可产生一条新意图。旧 `SUPPRESSED` 行保持原样，新行使用由旧 ID 派生的确定性指纹，仍受唯一约束、语义去重、冷却与频率限制。冷却、爆发保护与优先级抑制继续沿用原有低噪声去重。

未新增执行器、授权类型或任务状态机。`allow_medium=false`、Task TTL 600 秒、最多 16 步、最多 2 次重规划、同参无进展上限 3、Life 20 分钟冷却和每小时最多 3 条保持。实际既有 `MAX_PROPOSALS_PER_PASS` 为 **1**，比任务书所列上界 3 更严格，未扩大。

## 首次失败与修正

1. 首轮脚本在生产默认 300 秒恢复期内期待新目标，实际被正确抑制，零 Task；保留失败并改为自然等待，未改时钟或缩短恢复期。
2. 同小时恢复后无法重提的反例暴露了抑制历史指纹与新提议冲突；实现保留历史的新指纹路径，并验证 SQLite/内存幂等、睡眠/静默/冲突解除与原 24 小时低噪声约束。
3. `life-ac24170108ce` 暴露离线后短暂旧世界缓存仍被批准的问题；增加 runtime 直查、观察年龄及当前连接时间校验。
4. `life-14eec0c4e5fd` 的冲突门禁实际返回 `PENDING_CONFIRMATION`、创建 0 条。脚本把只读 `find_blocks`/`dig_capability` 的 action 事件误计为世界执行，导致断言失败；核对原始事件与独立坐标后修正分类，失败记录保留。
5. 部分中间测试受 Windows 沙盒 localhost socketpair 限制卡在事件循环建立前；诊断栈保留，使用正常本机访问权限执行测试。这类未进入用例的等待不记为 PASS。
