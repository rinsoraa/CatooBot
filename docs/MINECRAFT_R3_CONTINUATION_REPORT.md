## 2. 本轮实现

- 木材和通用采集计划的拾取参数改为引用该次 dig 的签名 `server_collection`，绑定精确实体 ID、UUID 和原始 break action；附近掉落物列表的首项不再充当来源证明。
- Python Service、任务适配器、工具 schema、HTTP client/runtime 与签名拾取预约传递相同关联。服务端预约校验 parent action；请求取消/超时与预约发布争用同一结果，失败发布不留下有效预约，nonce 仍不能重放。
- 显式冻结空手状态；规划检查观察新鲜度/覆盖与采收事实，真实 dig 前及异步预约后再次读取当前工具、耐久、附魔/组件和局部地形。严格证据关闭、手持变化、错误工具、耐久不足、未知邻域、支撑/地板缺失、邻近危险及上方重力块均保守拒绝。局部复核不等于所有路径和洞穴风险均已验收。
- 精确原版钩子观察破坏、实际接受的掉落实体生成、合并、实际收集者与库存增量。修正原版 pickup 在移除实体后恢复 ItemStack 数量用于统计的情况；无实际拾取变化的碰撞不提前污染来源账本。
- 拾取导航使用目标实体的精确整数格作为 GoalFollow 目标，保留原浮点拾取半径 1.2、最大距离 16 和 30 秒超时。修复相邻格被误判到达以及一格漂移不刷新目标的问题；没有放宽成功判据或预算。
- 等待 break/drop 两段证据时，第一次通知只唤醒复核；缺少必要证据会继续等到原截止时间。使用单调时间预算；重复轮询只建立一个拾取证明 waiter。

未增加执行器、授权类型或工具类别。技能、模型和记忆没有获得额外执行权限。
