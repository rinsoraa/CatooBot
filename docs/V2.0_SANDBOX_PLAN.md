## 一、旧架构审计（v1.2 现状，真实代码）

| 领域 | 现状 | 与 Sandbox 的关系 |
|---|---|---|
| WorldRuntime | 60s tick：routine 时段 → ActivityPlanner 在 transition window 内挑活动 → ActivityEpisode（min/typical/max + momentum）→ ambient/goals/snapshot | **核心冲突**：活动仍是"时段+窗口内挑选"，不是 Needs/Actions/Objects 驱动的因果链 |
| CharacterState | mood/energy/activity/location/social_state/current_goal/… | 保留，改为**只能由 SandboxStateManager 写入**（§77） |
| 记忆/关系/延续/社交/会话/媒体/Agent/响应 | v0.5-v1.2 已完成 | **保留**，通过 Adapter 接入（§84-§85） |
| WebUI /world | 世界页（时间线/作息/目标/模拟） | 降级为历史页；新增 `/sandbox` 全家桶 |

**关键发现**：旧 WorldRuntime 的 activity 选择确实存在"每次进入 transition 窗口重新决策"的结构；
v1.0 有 momentum/continuation 缓解，但状态机仍是**活动选择器**而非**生活模拟器**。
按 §186/§204，v2.0 不再补丁，改为 Sandbox 核心。

## 五、Sandbox 架构定案（步骤 3，§16/§19/§185）

```
CharacterBible(config/character_bible.md) → Compiler → SandboxSeed
    → EntitySystem(character + pet + objects) + SpaceSystem + Inventory + Needs
    → SandboxTick(10min, CPU/DB only):
         time → needs → entity state → object state → action progress →
         completion → scheduled → critical needs → external events → decision point?
    → SandboxDecisionEngine(候选生成 → 硬约束 → [必要时 LLM 结构化决策] → Validator)
    → SandboxStateManager(唯一写入者, 原子事务) → Trace/Snapshot/Timeline
    → 外部事件(QQ/Admin)：ExternalEvent → InterruptEvaluator → Decision
    → Context Provider → Conversation Runtime（既有，不重写）
```

**确定性**（§97/§189）：`simulation_seed` + 注入 clock；同一 state+rules+event 结果一致。
**LLM 边界**（§46/§124/§187）：默认 0 调用；仅多候选歧义时一次结构化 JSON → Validator → 状态写入。
